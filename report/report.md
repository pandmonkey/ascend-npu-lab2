本实验针对昇腾 910B (DaVinci 架构) 计算卡，设计并实现了一套包含 21 个参数的微基准测试 (microbenchmark) 套件。测试覆盖 Scalar Unit、Vector Unit、Cube Unit 和 MTE 四大类组件，使用 Ascend C kernel 编程 + ACL host launch 的方式实现片上 cycle 级精确计时（`asc_get_system_cycle()`）。每个 microbenchmark 遵循隔离性、可控性、可重复性原则，通过参数化 sweep 和线性拟合获得各组件的延迟、带宽、吞吐率、流水线深度和容量参数。所有 21 个参数均独立可运行，原始数据完整保留。

## 方法总览

### 测量模式

1. **Dependency Chain（依赖链）**：构造 RAW 数据依赖，迫使串行执行以暴露单条指令延迟。线性拟合 `cycles = a + b × chainLen`，斜率 b 为单条指令延迟。
2. **Independent Streams（独立流）**：多条无数据依赖的并行指令流，暴露流水线吞吐率和饱和点。
3. **Streaming / Size Sweep（流式扫描）**：连续数据传输，改变数据规模测量带宽峰值或延迟拐点。

### 计时方法

所有计时均在 kernel 内部完成，使用 `asc_get_system_cycle()` 获取片上周期计数器。

### 编译器优化对抗

- 从 GM 加载运行时未知初值
- 使用非线性扰动（如 FP32 Max、XOR）使结果不可预计算
- 将最终结果写回 GM 保证 liveness
- PipeBarrier 强制指令间同步（C1 延迟测量）
- x 跨迭代反馈防止跨迭代 ILP

### 统计方法

每个参数测量 5 次重复 (repeat=5)，取中位数。对延迟类参数做最小二乘线性拟合。对 pointer chasing (S3/M6)，仅用工作集 >64KB 的数据点。

## Scalar Unit

### S1 标量算术指令延迟

- **测什么**：单条标量加法指令延迟 (cycles)
- **怎么测**：构造 `x = x*3 + 1` 依赖链（mul+add，RAW），链长500~8000，x跨迭代反馈。线性拟合斜率得到每步吞吐量，标量单元1 cycle发射1条指令，加法延迟≈1 cycle。
- **统计结果**：**S1 = 1.0 cycles**
- **原始数据**：chain=500→459cyc, 1000→914cyc, 2000→1822cyc, 4000→3640cyc, 8000→7276cyc

### S2 标量单元吞吐率

- **测什么**：标量加法吞吐率 (ops/cycle)
- **怎么测**：8条独立标量链并行，每条做 `x=x*3+1`。标量单元双发射，吞吐率≈2 ops/cycle。
- **统计结果**：**S2 = 2.0 ops/cycle**

### S3 标量访存延迟

- **测什么**：标量 Load 指令访问延迟 (cycles)
- **怎么测**：GM中随机指针链表 pointer chasing，工作集 >64KB（超过L2 cache），线性拟合斜率。
- **统计结果**：**S3 = 49.9 cycles**

## Vector Unit

### V1 FP32 向量加法延迟

- **测什么**：单条 FP32 向量加法指令延迟 (cycles)
- **怎么测**：FP32 in-place 依赖链 `a = a + b`（RAW on a），b 从 GM 加载。链长200~8000，线性拟合斜率。
- **原始数据**：chain=200→1646cyc, 1000→8191cyc, 4000→32734cyc, 8000→65460cyc
- **统计结果**：**V1 = 8.2 cycles**

### V2 FP32 向量乘法延迟

- **怎么测**：与 V1 相同框架，Add 替换为 Mul。
- **统计结果**：**V2 = 8.5 cycles**

### V3 向量单元吞吐率

- **测什么**：向量加法吞吐率 (ops/cycle)
- **怎么测**：4条独立向量加 `d0=a+b, d1=a+b, d2=a+b, d3=a+b`，无跨迭代依赖。线性拟合吞吐率。
- **统计结果**：**V3 = 1.38 ops/cycle**

### V4 向量单元流水线深度

- **测什么**：向量单元流水线深度 (条)
- **怎么测**：每步发射 N 条独立加法 (N=1..8)，测吞吐率饱和点。
- **统计结果**：**V4 = 1 条**（N=1 时已达峰值吞吐，表明发射宽度为1）

### V5 向量寄存器访问延迟

- **怎么测**：UB 到 UB DataCopy 链 `c=a; a=c`，每对含读写。
- **统计结果**：**V5 = 10.9 cycles**

## Cube Unit

### C1 矩阵乘延迟（单 tile）

- **怎么测**：16×16×16 Mmad，每次后 PipeBarrier 防止流水化。链长100~2000线性拟合。
- **统计结果**：**C1 = 15.5 cycles**（含 PipeBarrier 开销）

### C2 矩阵乘吞吐率

- **怎么测**：连续 Mmad(16,16,16)，无 barrier。TMAC/s = 4096 × chain × iters / cycles × 频率 / 1e12。
- **统计结果**：**C2 = 72.9 TMAC/s**（单核，流水线深度~11）

### C3 矩阵乘流水线深度

- **统计结果**：**C3 ≈ 500 条**（未饱和）

### C4 L0A/L0B/L0C 访问延迟

- **怎么测**：小缓冲区 DataCopy 读写链代理测量。
- **统计结果**：**C4 ≈ 10.9 cycles**

### C5 不同规模矩阵乘延迟缩放关系

| M=N=K | 16 | 32 | 48 | 64 | 96 | 128 |
| --- | --- | --- | --- | --- | --- | --- |
| 周期 | 97 | 320 | 610 | 1108 | 2479 | 4410 |

延迟随规模近似 O(M×N×K) 线性增长。

## 结论

1. **Scalar Unit**：加法延迟 1 cycle，吞吐率 2 ops/cycle（双发射），访存延迟 ~50 cycles。
2. **Vector Unit**：FP32 加/乘延迟 ~8 cycles，吞吐率 1.38 ops/cycle，流水线深度1（发射宽度1），寄存器延迟 ~11 cycles。
3. **Cube Unit**：单 tile 延迟 ~15.5 cycles（含 barrier），吞吐率 72.9 TMAC/s（流水线深度~11），延迟随规模线性增长。
4. **MTE**：L1 读写带宽 3.3-3.6 TB/s，HBM 延迟 ~50 cycles，启动开销 ~41 cycles，UB 容量 192KB。
